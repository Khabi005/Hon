## Corrections to the Antigravity audit

The two supplied Antigravity attachments are identical. Its central gap list is useful, but several claims are too certain or proposed fixes need revision:

1. **Readium timeout:** waiting on a 15-second future and missing close settlement are confirmed. “Flutter messages are inevitably queued while another Activity is foregrounded” is not established by this source or an event trace. Holding `MethodChannel.Result` or marking every close as success can hide genuine load failures and conflate launch with readiness. Test the event sequence first.
2. **EPUB cover:** EPUB 2 metadata and image validation are real parser gaps. The *Lord of the Mysteries* EPUB itself was not supplied, so its exact cover cause cannot be declared. A backfill should be bounded/on demand, not heavy parsing on every library query.
3. **Rotation and continuous Readium:** the native manifest setting and `scroll` preference do not prove the exact rotation or resource-boundary mechanism. Prove behavior on device and check Readium 3.1.1 APIs before implementing drag interception or `firstVisibleElementLocator()` calls.
4. **Gutenberg URL:** the bundled Lua does concatenate the raw query in its `search` function. Whether OkHttp throws for a space was not demonstrated; the global Search screen never reaches this function. Its “No results found” is a separate, confirmed local-only search defect. Add a native spaced-query test before naming a second root cause.
5. **Extension repositories:** `index.json` plus script/library paths is a real Shosetsu convention, but the proposed schema, dependency resolution, `libVer`, licenses, and host APIs need fixture-driven verification across repositories. An MD5 match checks downloaded bytes, not publisher trust. A 15-second coroutine timeout alone cannot safely stop a non-cooperative LuaJ infinite loop.
6. **Safety priority:** duplicate workers, raw HTTP fallback, split SQLite writes, migration skips, and deletion races affect user data and external-script safety. They should be addressed before expanding arbitrary repository execution, rather than postponed wholesale to a final phase.
7. **Baseline language:** the current tree is not clean because of the pre-existing review XML files. Tests pass in this workspace, but the Kotlin Gradle task was up-to-date, and neither suite validates physical-device reader behavior.

## Bounded implementation sequence

1. **Safety and lifecycle checkpoint:** add event tracing/test seam for Readium open/ready/error/close; fix cancel/timeout/session handling. At the same time, block risky deletion/worker races and remove unsupported raw-HTTP execution. Keep the existing data intact.
2. **Cover and reader behavior checkpoint:** inspect the user's EPUB (when available), fix EPUB 2/3 extraction and backfill, real scroll/page behavior, preference persistence, and rotation/anchor handling. Preserve bookmarks/locators.
3. **Reader interface and sharing checkpoint:** align native EPUB controls with the downloaded-reader screenshots, deliver six functional themes if Readium API proof succeeds, and implement selected-quote sharing in native EPUB and Flutter downloaded reader. Validate PDF text selection separately.
4. **Search checkpoint:** replace local demo lookup with enabled-source async search, truthful per-source states, filters, and query-race protection. Test native Gutenberg with spaces and live upstream responses.
5. **Repository/settings checkpoint:** implement user-added Shosetsu repository lifecycle and the compatible Lua runtime/dependency contract, then organize persistent settings. Gate installation on proven execution limits, host/network restrictions, and worker script loading; preserve provenance and notices.
6. **Consolidated durability/acceptance:** finish migration/SQLite consistency, worker recovery/atomic completion, deletion retries, offline access, Android build, and physical-device checklist. Keep each checkpoint buildable and update `PROGRESS.md` only with verified status.
